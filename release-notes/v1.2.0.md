# StakeOS v1.2.0

This release fixes a calling-data bug that hid 174 callings across the stake, and
unblocks the first sync on the Windows dashboard.

## Highlights

### Fixes

- **Callings that were sustained but not yet set apart no longer disappear.** LCR's
  "Callings with Date Sustained and Set Apart" column reports each calling as
  `Title (<date sustained> / <set apart Yes|No>)`. StakeOS read that trailing Yes/No as
  if it meant "is this calling current," so anyone sustained but not yet set apart was
  filed as a historical calling and vanished from their member page. Across the stake,
  **174 current callings were hidden this way.** Set-apart status is now tracked
  separately from whether a calling is current.

- **"Sustained, Not Set Apart" on the Stake Overview now reports reality.** The card
  relied on a set-apart *date*, but LCR only ever supplies a Yes/No — so the date was
  empty on every calling and the card flagged everyone recently sustained as pending,
  while filtering out the people who genuinely weren't set apart. It now uses the real
  set-apart flag.

- **The first sync works on the Windows dashboard.** Installing Chromium always failed
  on Windows, and Chromium is required before a sync can run. Node refuses to launch
  `.cmd` files (which is what `npm` and `npx` are on Windows) without a shell, so the
  install died with `EINVAL`. The error was then invisible: it came back as an
  unparseable page, and the only error banner sat far below the button — so the button
  looked dead. macOS was never affected.

- **Windows now stores data where the setup guide says it does.** The database path was
  hardcoded to macOS's `~/Library/Application Support` on every platform, so Windows ran
  two different databases: the app wrote to a fake `Library` folder inside the user's
  profile while setup inspected `%APPDATA%`. A completed first sync was therefore never
  recognised. The macOS location is unchanged.

- **A sync that fails to launch no longer reports success.**

### Improvements

- Member pages show set-apart status per calling, with a **Not set apart** badge.
- New **Calling List Mismatches** card cross-checks LCR's plain `Callings` column against
  the dated column to surface disagreements between the two.

## Action Required After Updating

**Run a full sync (or a calling sync) to pick up the corrected callings.** The fix
changes how callings are read from LCR, so hidden callings reappear only once the data
is re-read. Nothing changes until you sync.

## Install Notes

- Download the `.dmg` for the standard macOS install flow.
- Use the `.zip` if the DMG is blocked or you need the app bundle directly.
- If macOS blocks first launch, right-click the app and choose **Open**.
- Windows users: see
  [WINDOWS_DASHBOARD_SETUP.md](https://github.com/naugsco/stakeos/blob/main/WINDOWS_DASHBOARD_SETUP.md).
  Windows runs from source, so pull this version to get the sync fix.

## Suggested Validation

- Open a member who holds a calling they haven't been set apart to yet and confirm it
  appears under **Current Callings** with a **Not set apart** badge (after syncing).
- Check **Stake Overview → Sustained, Not Set Apart** against LCR.
- On Windows, confirm the first sync starts, and that any failure now shows a message
  next to the button.

## Known Limitations

- The Windows fixes are derived from the code and Node's documented `.cmd` behaviour;
  they have not been exercised on a Windows machine.
- The Calling List Mismatches cross-check reads 0 until a sync populates the plain
  `Callings` column for the first time.
