# StakeOS v1.2.2

Ministering data has been missing from every sync since **4 May 2026**. All 4,230 members
imported with their ministering assignments empty, so the dashboard reported 0% ministering
coverage stake-wide and no recent convert as either ministered to or serving as a minister.

The data was never lost in LCR — the sync stopped reading it. **This release requires a sync**
to repopulate.

v1.2.1 noted that the ministering tools "return nothing until a sync populates the ministering
columns." This is why those syncs were not populating them.

## Highlights

### Fixes

- **Ministering assignments imported empty for four months.** Around 4 May 2026 LCR began
  serving its custom report with machine-key column headers instead of friendly labels. The
  parser was taught the machine keys for name, email, phone, unit, address, birthdate and
  callings, but not for ministering — and LCR's machine keys still use the pre-2018
  *home teacher / visiting teacher* terminology, so the aliases matched nothing:

  | Field | LCR machine key |
  | --- | --- |
  | Ministering Brothers | `record.home.teachers` |
  | Ministering Sisters | `record.visiting.teachers` |
  | Has Ministering Brothers | `custom-reports.has.home.teachers` |
  | Has Ministering Sisters | `custom-reports.has.visiting.teachers` |

  Every row still imported and every sync still reported success, which is why this went
  unnoticed. After syncing, **981 members** have ministering assignments again.

- **Born in Covenant was false for everyone.** The same mismatch — LCR's key is
  `custom-reports.is.bic`, not "Is Born in Covenant". 967 members were flagged
  `Born in Covenant` under Sealing to Parents while the boolean read false. Both now agree.

- **Is Sealed to a Prior Spouse never imported.** LCR's key omits the "a"
  (`custom-reports.is.sealed.to.prior.spouse`). Not stored in the database, so no report
  changed, but the field now parses.

- **Mission status is now derived.** This report has no Mission column, so the field was
  always empty. It is now deduced from Mission Country, Mission Language, and Is Returned
  Missionary, and resolves to `Returned Missionary` for **517 members**.

- **`currently_serving_missionaries` would have reported every returned missionary as
  actively serving.** It matched on mission status being non-null, so populating that field
  would have returned all 517. It now requires mission data *without* the returned-missionary
  flag.

### Added

- **Syncs now refuse to overwrite good data with empty columns.** Before persisting, a sync
  compares the incoming scrape against what is already stored and aborts if a populated field
  arrives completely empty, naming each field and its stored count. The database is left
  untouched. Had this existed, the ministering break would have surfaced on 5 May rather than
  four months later.

  Seminary and institute enrolment are deliberately exempt — they legitimately fall to zero
  stake-wide each summer when seminary is not in session.

## Action Required After Updating

**Run a full sync.** These are parser fixes; existing rows in the database are not rewritten
until the next sync reimports them.

## Install Notes

- Download the `.dmg` for the standard macOS install flow.
- Use the `.zip` if the DMG is blocked or you need the app bundle directly.
- This build is unsigned and not notarized. If macOS blocks first launch, right-click the app
  and choose **Open**, or use **System Settings > Privacy & Security > Open Anyway**.
- If macOS still blocks it, run
  `xattr -dr com.apple.quarantine "/Applications/StakeOS Desktop.app"` and try again.
- Windows users: see
  [WINDOWS_DASHBOARD_SETUP.md](https://github.com/naugsco/stakeos/blob/main/WINDOWS_DASHBOARD_SETUP.md).
  Windows runs from source, so pull this version to get these fixes.

## Suggested Validation

- Run a sync, then open the recent-baptism unit heat map and readiness cohort. Converts from
  the last 24 months should now show assigned ministers, and some should show as serving as a
  minister themselves.
- Ask for ministering assignments for a member you know is assigned, and confirm both brothers
  and sisters come back.
- Check `unit_ministering_coverage` for a ward and confirm it is no longer 0 assigned.

## Known Limitations

- **Currently-serving missionaries still cannot be identified.** LCR's report offers no column
  for it, and Mission Country and Mission Language only ever populate alongside the
  returned-missionary flag — no member in the stake has one without the other. That report
  will keep returning nothing until LCR exposes a suitable column.
- Mission status distinguishes only `Returned Missionary` from no mission history. It carries
  no information about a mission in progress.
- The coverage guard only fires when a field drops to *completely* empty. A partial collapse —
  for example 981 assignments falling to 20 — still passes.
- Seminary and institute fields are exempt from the guard, so a genuine break in those columns
  would still go unnoticed until someone checked during the school year.
